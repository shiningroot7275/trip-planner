# 개발·디버깅 안내

이 문서는 플래너를 고치거나 문제를 찾을 때 보는 안내입니다. 쓰는 방법은 [README](../README.md)에 있습니다. 코드를 찾아가야 하는 문서라서 파일 이름과 함수 이름을 그대로 적었습니다.

## 1. 구조

`index.html` 한 파일로 동작합니다. 이 파일은 `src/`의 조각을 번호 순서대로 이어 붙여 만들므로, `index.html`을 직접 고치지 않습니다.

| 파일 | 담당 |
|---|---|
| `src/01_head.html` | 문서 머리, 색과 글꼴 값, 앱 뼈대와 지도, 정보창 스타일 |
| `src/02_body.html` | 목록, 시간표, 항공권, 더보기, 대화상자 스타일과 화면 뼈대, 외부 스크립트(Leaflet 1.9.4, `lz-string` 1.5.0) |
| `src/03_core.js` | 공용 도구, 날짜 계산, 그림 기호, 장소 분류, 자료 정리(`normTrip`), 운영시간 판정(`hoursCheck`), 페이지 버전(`APP_BUILD`) |
| `src/04_seed.js` | 예시 장소 12곳. `04_make_seed.py`가 만들므로 직접 고치지 않음 |
| `src/05_state.js` | 예시 여행과 예시 시간표, 저장, 항공편 시각 계산, 이동시간 계산 |
| `src/06_map.js` | 지도, 장소 표시, 장소 정보창, 이동시간 창, 내 위치, 장소 검색, 위치 지정 |
| `src/07_plan.js` | 장소 목록, 시간표, 끌어다 놓기 |
| `src/08_forms.js` | 대화상자, 알림, 일정·장소 입력 |
| `src/09_flights.js` | 항공권 화면 |
| `src/10_more.js` | 준비물, 여행 설정, 공유 링크·백업, 여행 목록 |
| `src/11_init.js` | 탭 전환, 버튼 연결, 새 버전 확인, 시작 |
| `src/12_build.sh` | 조각을 이어 붙이고 빌드 시각을 `APP_BUILD`에 넣어 `index.html`을 만듦 |
| `tests/01_osm_hours_test.js` | OpenStreetMap 운영시간 읽기 시험 |

## 2. 고치고 올리는 순서

1. `src/` 조각을 고칩니다.
2. 예시 장소 자료를 바꿨다면 예시 파일을 다시 만듭니다.

   ```sh
   python -I src/04_make_seed.py data/01_places_hk_2027-01.json src/04_seed.js
   ```

3. `index.html`을 만듭니다. 빌드 시각이 페이지 버전이 됩니다.

   ```sh
   sh src/12_build.sh
   ```

4. 스크립트 문법을 점검합니다.

   ```sh
   python -I -c "s=open('index.html',encoding='utf-8').read(); open('_check.js','w',encoding='utf-8').write(s.split('lz-string.min.js\"></script>\n<script>',1)[1].rsplit('</script>',1)[0])" && node --check _check.js && rm _check.js
   ```

   운영시간 읽기를 고쳤다면 `node tests/01_osm_hours_test.js`도 실행합니다.
5. 컴퓨터에서 확인합니다. `python -m http.server 8765`를 실행하고 `http://localhost:8765/index.html`을 휴대폰 크기(가로 375픽셀)로 엽니다.
6. GitHub에 올립니다. Pages가 1분 안팎에 다시 만들어지면 올라간 버전을 확인합니다.

   ```sh
   curl -s "https://shiningroot7275.github.io/trip-planner/?check=$(date +%s)" | grep -o "const APP_BUILD = '[0-9]*'"
   ```

## 3. 저장

- 브라우저 저장소(`localStorage`)에 두 항목을 씁니다.
  - `tripPlanner.v1`: 여행 전체와 화면 설정
  - `tripPlanner.routes.v1`: 경로 계산 결과(최대 250개)
- 저장은 브라우저 앱마다 따로입니다. 카카오톡 안 브라우저, Safari, Chrome, 홈 화면 아이콘이 각각 다른 저장소를 씁니다.
- 예시 여행(`hk-2027-01`)을 한 번도 고치지 않았다면(`updatedAt`이 0), 열 때 최신 예시로 바뀝니다. 한 번이라도 고쳤다면 그대로 두고, 더보기의 "예시 시간표 넣기"로만 예시 일정을 넣을 수 있습니다.

## 4. 공유 링크

- **새 형식:** `#t=` 뒤에 종류 글자 하나와 `base64url` 글자(A–Z, a–z, 0–9, `-`, `_`)가 붙습니다.
  - `D`: 브라우저의 `deflate-raw` 압축(`CompressionStream`)
  - `L`: `lz-string` 압축. 압축 기능이 없는 오래된 브라우저에서 씁니다.
- **줄이는 방법:** 예시 장소는 이름표와 달라진 항목만 보냅니다. 예시 일정과 예시 준비물은 이름표만 보냅니다(`packTrip`, `unpackTrip`). 받는 페이지가 자기 예시 자료로 나머지를 채웁니다.
- **만든 직후 확인:** 링크를 다시 풀어 지금 일정과 같은지 비교하고, 다르면 링크를 내주지 않습니다.
- **예전 형식(`#share=`):** 계속 읽습니다. `+`가 띄어쓰기나 `%2B`로 바뀐 경우도 읽습니다(`decodeShareV1`).
- **받는 쪽:** 같은 여행이 없거나 한 번도 고치지 않았으면 바로 가져옵니다. 고친 적이 있으면 덮어쓸지 묻습니다.
- **길이 기준:** 예시 장소 6곳을 고치고 장소와 일정을 하나씩 더한 일정에서 약 1,400자였습니다(2026-11-19 측정). 2,000자를 넘으면 공유 창에 백업 파일을 권하는 안내가 뜹니다.

## 5. 새 버전 안내

- `APP_BUILD`는 빌드 시각 12자리(연월일시분)입니다. 더보기 맨 아래에 "페이지 버전"으로 보입니다.
- 페이지를 열고 1.5초 뒤, 화면으로 돌아왔을 때, 뒤로 가기로 다시 보일 때 `index.html`을 캐시 없이 받아 버전을 비교합니다(`checkUpdate`).
- 더 새로운 버전이 있으면 알림을 띄웁니다. 그 상태에서 공유 링크를 만들려고 하면 막고 새로 고침을 안내합니다. 새로 고침은 주소 뒤에 `?v=버전`을 붙여 저장된 예전 페이지를 피합니다.
- GitHub Pages는 페이지를 최대 10분 동안 캐시하도록 응답합니다(`Cache-Control: max-age=600`).

## 6. 검색 자동 입력

- 검색 결과를 고르거나 지도를 길게 누르면 OpenStreetMap 정보로 장소 입력 칸을 채웁니다(`fromOSM`).
- 채우는 칸은 이름(한국어 이름 우선), 현지 이름, 분류, 좌표, 주소, 웹사이트, 운영시간, 메모(전화번호, 음식 종류)입니다.
- 운영시간 읽기(`parseOSMHours`)는 다음 규칙을 따릅니다.
  - 공휴일(PH) 규칙은 요일에서 빼고 "공휴일 운영시간은 따로 정해져 있습니다"를 남깁니다.
  - 따옴표 안의 설명은 "OpenStreetMap 설명"으로 옮깁니다.
  - 표기에 나오지 않는 요일은 휴무로 봅니다(OpenStreetMap 표기 규칙).
  - 월·날짜 지정, 일출·일몰, 끝 시각 없는 표기가 있으면 읽지 않고 원래 표기만 남깁니다.
- 자동으로 채운 운영시간에는 "기타 출처 확인 (다시 확인 권장)", 가져온 날, OpenStreetMap 원래 표기를 함께 남깁니다.
- 검색 결과에는 장소 종류(식당, 박물관, 버스 정류장 등)와 "운영시간 있음", "전화번호 있음" 표시가 붙습니다.
- 측정(2026-11-19): 홍콩 여행 장소 20곳 가운데 운영시간이 있는 곳은 10곳이었고, 읽은 곳은 이전 6곳에서 10곳으로 늘었습니다. 웹사이트는 8곳, 전화번호는 3곳에 있었습니다.
- 시험: `node tests/01_osm_hours_test.js` (실제 표기 10건과 경계 사례)

## 7. 외부 서비스

| 용도 | 서비스 | 조건 |
|---|---|---|
| 지도 그림 | OpenStreetMap 표준 타일 | 키 없음. 어두운 화면에서는 CSS 필터로 밝기를 뒤집음 |
| 장소 검색, 검색 자동 입력 | OpenStreetMap Nominatim | 검색 버튼을 누를 때만, 1.1초 이상 간격 |
| 도보·차량 시간 | FOSSGIS OSRM (`routing.openstreetmap.de`) | 한 번에 하나씩, 1.1초 이상 간격 |
| 대중교통 시간 | 자체 추정 | 도보·차량 경로거리 중 짧은 쪽 ÷ 평균 속도(20~40km/h) + 10분 |

- CARTO 지도는 2026-11-18 확인 당시 API 키를 요구해 쓰지 않습니다.
- 구글 지도, Firebase처럼 API 키나 프로젝트 설정이 필요한 연결은 쓰지 않기로 했습니다(2026-11-19 사용자 결정).

## 8. 지금까지 겪은 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| 지도에 "API KEY REQUIRED"가 보임 | CARTO 지도가 키를 요구함 | OpenStreetMap 표준 타일로 바꿈 |
| 일부 버튼이 화면 왼쪽 위에 붙음 | 끌기 미리보기 이름(`ghost`)이 버튼 모양 이름과 겹침 | 미리보기 이름을 `drag-ghost`로 바꿈 |
| 아이폰에서 날짜·시각 입력칸이 카드 밖으로 넘침 | 아이폰 날짜·시각 입력칸의 기본 최소 너비 | 기본 모양을 끄고, 격자 칸이 내용보다 좁아질 수 있게 하고, 항공권 칸을 두 줄로 나눔 |
| 대중교통 추정이 지나치게 김 | 바다 건너는 구간에서 차량 경로(해저터널 우회) 거리를 씀 | 도보(스타페리 포함)와 차량 경로 중 짧은 거리를 씀 |
| 공유 링크가 카카오톡에서 열리지 않음 | 링크가 9,784자이고 `+`가 101개 들어감 | 4절의 새 형식 |
| 고친 뒤에도 9,000자 넘는 링크가 만들어짐 | 휴대폰이 예전 페이지를 계속 씀(캐시, 열어 둔 화면) | 5절의 새 버전 안내 |
| 처음 받는 사람에게 "같은 여행이 있다"고 물음 | 예시 여행과 받은 여행의 이름표가 같음 | 고친 적 없는 예시면 바로 가져옴 |
| 1일차 시간표 일정이 처음 화면에 안 보임 | 처음 위치를 오전 9시 근처로 고정함 | 그날 첫 일정 위치로 이동 |
| 검색한 장소의 운영시간이 절반쯤만 채워짐 | 공휴일 표시나 설명 문구가 섞인 표기를 통째로 포기함 | 6절의 운영시간 읽기 강화 |
| 장소가 있는데도 "찾은 장소가 없습니다"가 뜸 | 지도가 숨겨졌거나 아주 넓을 때 검색 범위 값이 잘못되어 검색 서버가 오류를 돌려줌 | 범위가 올바를 때만 보내고, 서버 오류는 연결 오류로 안내 |

**휴대폰에서 문제가 생기면 페이지 버전부터 확인합니다.** 더보기 맨 아래의 버전이 GitHub에 올린 버전과 다르면 예전 페이지 문제입니다.

## 9. 고친 뒤 점검 목록

- 지도가 보이고, 장소 표시를 누르면 정보창, 다른 표시를 누르면 이동시간이 나온다
- 장소를 검색해 고르면 운영시간과 출처가 채워진다
- 시간표로 끌어다 놓으면 시각 입력창이 열리고, 일정 사이 이동시간과 경고가 붙는다
- 항공권 시각을 넣으면 시간표에 항공편이 보이고 비행시간이 맞다
- 공유 링크를 만들어 저장소를 비운 브라우저에서 열면 같은 일정이 들어온다
- 휴대폰 크기(가로 375픽셀)와 어두운 화면에서 칸이 넘치지 않는다
- 브라우저 콘솔에 오류가 없다

## 10. 알려진 한계

- 실시간 연동이 없습니다. 일정은 공유 링크나 백업 파일로 넘깁니다.
- 대중교통 시간은 추정치입니다. 실제 시간은 구글 지도 버튼으로 확인합니다.
- 홍콩 지도 글자는 중국어와 영어로 나옵니다.
- 아이폰 Safari는 오래 열지 않은 사이트의 저장 자료를 지울 수 있습니다.
- 예시 장소 운영시간은 2026-11-18에 확인한 값입니다.
